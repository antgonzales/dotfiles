# Flowchart diagrams

- Use flowcharts with standard symbols: oval for start and end, rectangle for steps, diamond for decisions. Do not use UML sequence diagrams unless asked.
- Give every chart an obvious first step and a single reading direction.
- Use swimlanes for each system that owns a step, including the server.
- Show only what a reader needs at a glance. Move detail into a legend or the text.
- When comparing current and proposed states, draw both at the same level of detail. Stay fair to the current state.
- Label state owners on the steps they own, such as the library or event that holds the data.

# Technical claims

- Verify every claim against code, configuration, or data before writing it. Mark anything inferred as inferred.
- State the exact scope. Do not write "X is untested" when unit tests cover X; name the layer that covers it and the layer that does not.
- State structural facts, not judgments. Do not call another team's system "opaque" or "undocumented"; describe what exists.
- Stay neutral about the current system and its owners. Sensitivity comes from neutral facts, not softened language. Assign no blame.
- Do not state the obvious or list what every reader already knows.
- Do not define widely known terms. Define only what a peer outside the team would not know.

Related: `writing-voice`.
